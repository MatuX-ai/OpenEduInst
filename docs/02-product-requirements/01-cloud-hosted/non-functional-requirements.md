## NFR-PERF — 性能要求

### NFR-PERF-001 — 页面首屏加载

- **描述**：用户访问系统任意主要页面的首屏加载时间应在可接受范围内
- **指标**：首屏加载时间 < 2 秒（桌面端，网络正常网络）
- **测量方式**：Lighthouse Performance 评分；实际用户体验
- **优先级**：P0
- **状态**：✅ 已实现（基础架构支持

### NFR-PERF-002 — API 响应时间

- **描述**：所有 API 接口在标准负载下的响应时间应在可接受范围
- **指标**：API 平均响应时间 < 500ms；API P99 响应时间 < 2 秒
- **测量方式**：基于请求日志分析
- **优先级**：P0
- **状态**：✅ 已实现

### NFR-PERF-003 — 并发用户数

- **描述**：系统应支持同时在线使用的用户规模
- **指标**：支持 ≥ 500 并发用户在线使用
- **测量方式**：JMeter 并发测试
- **优先级**：P0
- **状态**：✅ 基础架构支持

### NFR-PERF-004 — 数据库查询性能

- **描述**：数据库查询响应时间应在可接受范围
- **指标**：数据库查询响应 < 200ms（标准查询）
- **测量方式**：数据库慢查询日志分析
- **优先级**：P1
- **状态**：✅ 已实现

### NFR-PERF-005 — WebSocket 消息延迟

- **描述**：实时消息推送的延迟应在可接受范围
- **指标**：WebSocket 消息延迟 < 100ms
- **测量方式**：端到端延迟测量
- **优先级**：P1
- **状态**：✅ 已实现

### NFR-PERF-006 — 列表代理接口性能

- **描述**：OpenSciEd 资源的代理接口响应时间应在可接受范围
- **指标**：列表代理 P95 < 2s（含上游响应时间）
- **测量方式**：接口响应时间监控
- **优先级**：P1
- **状态**：✅ 已实现（Redis 缓存 TTL 可配置）

## NFR-AVAIL — 可用性要求

### NFR-AVAIL-001 — 系统可用性 SLA

- **描述**：系统对外服务的可用性承诺
- **指标**：系统可用性 (SLA) ≥ 99.5%（月度）
- **测量方式**：uptime 监控
- **优先级**：P0
- **状态**：✅ 已实现（基础架构支持）

### NFR-AVAIL-002 — 计划内维护窗口

- **描述**：系统可进行计划内维护的时间窗口
- **指标**：每月 1 次计划维护，凌晨 02:00-04:00（UTC+8）
- **优先级**：P2
- **状态**：✅ 已规划

### NFR-AVAIL-003 — 故障恢复时间

- **描述**：系统发生故障后的恢复时间目标
- **指标**：故障恢复时间 (RTO) ≤ 4 小时
- **优先级**：P0
- **状态**：✅ 已实现（基于备份恢复机制）

### NFR-AVAIL-004 — 数据恢复点

- **描述**：可接受的最大数据丢失量对应的时间点
- **指标**：数据恢复点 (RPO) ≤ 24 小时
- **优先级**：P0
- **状态**：✅ 已实现（每日备份策略）

### NFR-AVAIL-005 — 上游不可用降级

- **描述**：当上游服务不可用时，前端不应白屏
- **规格**：OpenSciEd 上游不可用时，显示友好的空态和重试按钮
- **优先级**：P1
- **状态**：✅ 已实现

## NFR-SCALE — 可扩展性

### NFR-SCALE-001 — 机构数量扩展

- **描述**：系统应能支持大量机构接入
- **指标**：支持 1000+ 机构
- **测量方式**：架构设计支持水平扩展
- **优先级**：P1
- **状态**：✅ 已实现（多租户架构设计）

### NFR-SCALE-002 — 单机构学员数扩展

- **描述**：单个机构应能支持大量学员
- **指标**：单机构支持 10,000+ 学员
- **优先级**：P1
- **状态**：✅ 已实现（数据模型设计）

### NFR-SCALE-003 — 数据量扩展

- **描述**：系统应能支持 TB 级数据量
- **指标**：总数据量 TB 级
- **优先级**：P1
- **状态**：✅ 已实现（基于 PostgreSQL + S3 架构）

### NFR-SCALE-004 — 水平扩展支持

- **描述**：系统应能通过增加应用服务器实例进行扩展
- **规格**：应用层无状态，可水平扩展
- **优先级**：P1
- **状态**：✅ 已实现（FastAPI + Uvicorn 架构）

## NFR-SEC — 安全合规

### NFR-SEC-001 — 传输加密

- **描述**：全站强制 HTTPS 加密传输
- **规格**：使用 TLS 1.2+ 加密传输
- **优先级**：P0
- **状态**：✅ 已实现（HSTS 已启用）

### NFR-SEC-002 — 数据存储加密

- **描述**：敏感数据加密存储
- **规格**：敏感字段（手机号、身份证号）AES-256 加密存储
- **优先级**：P1
- **状态**：🎯 待实现

### NFR-SEC-003 — 个人信息保护法合规

- **描述**：符合个人信息保护法要求
- **规格**：用户有权删除个人数据；数据最小化原则；数据导出功能
- **优先级**：P1
- **状态**：✅ 基础实现；🎯 完整合规流程待完善

### NFR-SEC-004 — 教育行业数据安全

- **描述**：符合教育行业数据安全标准
- **规格**：学生数据不出境；符合教育部信息化安全规范
- **优先级**：P1
- **状态**：✅ 基础实现

### NFR-SEC-005 — API Key 安全

- **描述**：第三方 API Key 不得出现在前端 bundle 或日志中
- **规格**：所有 API Key 仅存储于后端；日志中自动脱敏；禁止前端直接调用
- **优先级**：P0
- **状态**：✅ 已实现

### NFR-SEC-006 — 审计合规

- **描述**：关键操作审计日志保留 ≥ 1 年
- **规格**：记录所有关键操作的审计日志
- **优先级**：P1
- **状态**：✅ 已实现

## NFR-COMPAT — 兼容性要求

### NFR-COMPAT-001 — 浏览器兼容性

- **描述**：系统应支持主流浏览器
- **规格**：Google Chrome 90+；Microsoft Edge 90+；Safari (macOS/iOS) 14+；Firefox 90+
- **优先级**：P1
- **状态**：✅ 已实现

### NFR-COMPAT-002 — 移动端浏览器

- **描述**：系统应在移动端浏览器正常工作
- **规格**：iOS Safari 14+；Android Chrome 90+
- **优先级**：P1
- **状态**：✅ 已实现

### NFR-COMPAT-003 — 响应式布局

- **描述**：系统在各种屏幕尺寸下有合适的布局
- **规格**：桌面端（1280px+）；平板端（768-1024px）；移动端（<768px）
- **优先级**：P1
- **状态**：✅ 已实现（Angular Material 响应式）

### NFR-COMPAT-004 — 软件依赖版本

- **描述**：系统使用的关键软件版本
- **规格**：Python 3.9+；Node.js 18+；PostgreSQL 15+；Redis 7+；Docker 24+
- **优先级**：P0
- **状态**：✅ 已实现
